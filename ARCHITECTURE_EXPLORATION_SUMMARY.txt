PERFORMANCE CHARACTERISTICS
============================

Current Performance (Ollama):
  - Chat response time: 3-5+ seconds
  - Embedding generation: ~50 tokens/sec
  - Embedding calls per query: 20-40
  - Sequential processing (no batching)

Optimization Roadmap:
  - Planned Groq migration: 10-20x faster LLM
  - Planned Voyage AI: Superior embedding quality
  - Semantic filtering: Reduce context size by 50%
  - Response caching: <100ms for repeated queries
  - Batch processing: Handle 5-10 embeddings at once

Cost Analysis (Post-Migration):
  - LLM (Groq): ~$3/day
  - Embeddings (Voyage): ~$2/day
  - Total: ~$150/month for 10K queries/day

MULTI-TENANCY ARCHITECTURE
===========================

Isolation Levels:
  1. Application Level: Tenant ID from JWT
  2. Database Level: WHERE tenant_id = X filters
  3. Widget Level: Domain whitelist (CORS)
  4. Rate Limiting: Per-tenant limits
  5. Storage: Separate embeddings per tenant
  6. Configuration: Per-tenant branding
  7. Audit: Per-tenant action logging

Security Measures:
  - Bearer token authentication
  - JWT verification on every request
  - Password hashing (bcrypt for superadmins)
  - CORS domain validation
  - IP whitelist support
  - Admin session expiration
  - Comprehensive audit logging
  - Rate limiting DoS protection

ARCHITECTURAL DECISIONS
=======================

Strengths:
  - Clear separation of concerns (Frontend, API, Core, Data)
  - Strong multi-tenant isolation (database-enforced)
  - Flexible configuration (white-label support)
  - Comprehensive API surface (all CRUD operations)
  - Security-first design (CORS, rate limiting, audit)
  - Scalable database indexing strategy

Areas for Improvement:
  - Single monolithic FastAPI (ready for decomposition)
  - Ollama self-hosted (bottleneck for performance)
  - No explicit task queue (Celery/RQ missing)
  - Legacy Streamlit app alongside React UIs
  - Optional Redis integration (not fully utilized)
  - Direct Ollama client calls (no abstraction layer)

READINESS FOR MICROSERVICES MIGRATION
======================================

The platform is well-architected for microservices decomposition:

Recommended Service Boundaries:
  1. Auth Service - Cognito wrapper + JWT management
  2. Document Service - Upload, validation, storage
  3. Embedding Service - Ollama abstraction, caching
  4. RAG/Chat Service - Core inference engine
  5. Widget Service - Configuration, embed script
  6. Admin Service - Tenant dashboard, profiles
  7. Super Admin Service - Platform management
  8. Analytics Service - Usage tracking, reporting

Shared Infrastructure:
  - PostgreSQL (multi-schema approach)
  - Redis (centralized cache)
  - Ollama (dedicated microservice)
  - AWS Cognito (external auth provider)

Migration Benefits:
  - Independent scaling per service
  - Technology diversity per service
  - Fault isolation and resilience
  - Simplified deployment and testing
  - Better resource allocation
